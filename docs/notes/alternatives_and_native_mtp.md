# Alternatives to EAGLE for retrofitting multi-token drafting, and natively trained MTP modules (as of November 2026)

Conventions used throughout:
- "Speedup" is wall-clock versus autoregressive decoding of the same model at batch size 1 unless noted. "τ" / "MAT" / "acceptance length" is tokens committed per target forward pass (most papers include the one guaranteed "bonus" token; exceptions are flagged).
- "Lossless" means greedy exact-match (or speculative-sampling) verification, so output equals the base model's own output.
- Numbers were read from the primary PDFs (arXiv full text) unless a different source is named. "(derived)" marks my arithmetic. "Not stated" means the source was checked and the item is absent.
- Cross-paper speedups are not comparable: the same method (Medusa-1 on Vicuna-7B, MT-Bench, greedy) is reported at 2.18x, 2.13x, 2.00x, 1.87x and 1.55x by five different papers on different hardware (see the head-to-head section).

## 1. Retrofitted heads on a frozen (or lightly tuned) base model

### Takeaway
Every non-EAGLE head family converges on the same lesson: parallel heads that see only the last hidden state (Medusa) plateau at about 60% per-token acceptance and roughly 1.5-2.2x, and making the draft sequentially dependent on the previously drafted token's embedding (Hydra, Clover, Falcon, the DeepSeek/Qwen MTP block) lifts acceptance to 75-80% and speedup to roughly 2.0-3.0x on Vicuna-class models. All of them except Medusa-2 and the LoRA-based methods keep the trunk frozen, train on roughly 60-70k ShareGPT dialogues or a few hundred thousand self-distilled samples, and cost hours to a couple of GPU-days. The closest thing to the reader's exact plan has now been published: AngelSpec (Tencent, July 2026) trains a one-layer Qwen-style MTP block on frozen Qwen3-8B and gets a mean accepted length of 3.24.

### Cited Findings

**Medusa (Cai et al., ICML 2024)**
- Architecture: K extra heads on the last hidden state, head k predicts position t+k+1; each is one residual block `softmax(W2 (SiLU(W1 h) + h))` with W1 d x d (zero init) and W2 d x V (initialised from the LM head). Heads see only h_t, with no dependence on earlier draft tokens; candidates are a Cartesian product pruned to a 64-node sparse tree. 5 heads trained, 4 used. — [Medusa, Sec 2.1 and App B](https://arxiv.org/abs/2401.10774)
- Parameter count is not stated in the Medusa paper; Kangaroo reports 591M added parameters for Medusa on Vicuna-7B (matches 4 x (4096^2 + 4096 x 32000), derived), and ESP reports "~400M parameters for LLaMA3.2-3B-Instruct". — [Kangaroo, Table 2](https://arxiv.org/abs/2404.18911); [ESP](https://arxiv.org/abs/2603.17942)
- Medusa-1: backbone frozen, loss = sum over heads of lambda_k CE with lambda_k = 0.8^k. Training: ShareGPT 60k samples, 2 epochs; "5 hours for MEDUSA-1 on Vicuna 7B model with a single NVIDIA A100 PCIE GPU". — [Medusa, Sec 2.2.1, 3.1](https://arxiv.org/abs/2401.10774)
- Medusa-2: joint training with (a) combined loss L_LM + lambda0 L_Medusa-1 (lambda0 = 0.2 for 7B/13B, 0.01 for 33B/Zephyr), (b) heads LR 4x the backbone LR (5e-4 backbone, 2e-3 heads), (c) heads warm-up (Medusa-1 first, then joint). The backbone is tuned with LoRA/QLoRA rank 32 on all linear layers, never full fine-tuning. Medusa-2 GPU hours are not stated. — [Medusa, Sec 2.2.2, App B.2-B.4](https://arxiv.org/abs/2401.10774)
- Results (MT-Bench): Medusa-1 2.18x (Vicuna-7B), 2.33x (13B); Medusa-2 2.83x (7B), 2.83x (13B), 2.35x (33B), 2.66x (Zephyr-7B). Medusa-2 tokens per step 3.47 / 3.51 / 3.01 / 3.14 with overhead 1.22-1.27. Technique breakdown: heads alone ~1.5x, tree attention ~1.9x, optimised tree ~2.2x, Medusa-2 training ~2.8x. — [Medusa, Tables 1-3, Fig 3](https://arxiv.org/abs/2401.10774)
- Lossless only for Medusa-1 with greedy/rejection verification. "Typical acceptance" is lossy by design, and Medusa-2 changes the backbone (GPT-4 MT-Bench quality 6.18 vs 6.17 base on 7B, -0.14 on 13B). — [Medusa, Sec 2.3.1, Table 1](https://arxiv.org/abs/2401.10774)
- Independent per-token acceptance for Medusa on Vicuna-7B: 60.5% (MT-Bench) versus 74.6% for EAGLE-1. — [Falcon, Table 2](https://arxiv.org/abs/2412.12639)

**Hydra / Hydra++ (Ankner et al., COLM 2024)**
- Architecture: sequentially dependent heads. Head i is an MLP over the trunk hidden state concatenated with the input embeddings of the already drafted tokens. Hydra++ adds 4-layer MLPs, a distillation loss to the base model's own next-token distribution, and one extra self-attention decoder layer ("prefix attention") on top of the frozen trunk, queried once per step. 4 heads; parameter count not stated. — [Hydra, Sec 3, App A](https://arxiv.org/abs/2402.05109)
- Base model frozen: "in this work we only study base models with frozen weights." Data: ShareGPT, 1 epoch (Hydra) or 10 epochs (Hydra++). Compute: 8x A100-80GB, hours not stated. — [Hydra, Sec 5](https://arxiv.org/abs/2402.05109)
- Results (MT-Bench, greedy, A100): throughput Medusa 2.13x / 1.97x / 1.93x, Hydra 2.36x / 2.17x / 2.15x, Hydra++ 2.70x / 2.50x / 2.53x on Vicuna 7B / 13B / 33B; acceptance length Medusa 2.58, Hydra 3.04, Hydra++ 3.70 (7B). Against EAGLE-1 (retrained by the Hydra authors) on Vicuna-7B: Hydra++ throughput 1.01x of EAGLE, acceptance length 0.92x of EAGLE. Hydra++ falls from 2.70x at batch 1 to 1.63x at batch 8. — [Hydra, Fig 2, Sec 6.2, App C](https://arxiv.org/abs/2402.05109)
- Ablations: teacher (self-distillation) loss +4% throughput / +5% acceptance; extra prefix-attention layer about +8-11% throughput / +12-14% acceptance (paper's prose and figure disagree slightly); noise on hidden states hurts. Lossless (greedy) in the main results. — [Hydra, App A](https://arxiv.org/abs/2402.05109)

**Clover and Clover-2 (Baichuan)**
- Clover: 3 RNN-like heads with a "regressive connection" (previous speculated token's embedding feeds the next head through a small cross-attention), plus an "augmenting block" = one full extra transformer block on top of the frozen trunk, initialised from the trunk's last block; all heads share the original LM head. Trainable parameters "approximately 0.2B and 2B" for Baichuan-Small (7B) and Baichuan-Large (>100B). Frozen trunk. Data: internal SFT set, ~0.15B tokens, 1 epoch; 2 hours on 8x A800 (small) / 32x H800 (large). — [Clover, Sec 3-4](https://arxiv.org/abs/2405.00263)
- Clover results (internal benchmark, batch 4-48): up to +91% (small) / +146% (large) tokens/s over vanilla, 50-76% more extra tokens per step than Medusa; head top-5 accuracy 89.2 / 81.4 / 75.4% for heads 1-3; removing the augmenting block costs 4.3 / 8.1 / 8.9 points, removing the regressive connection 2.6 / 4.6 / 6.0. Speedup turns negative at batch 48 on the small model. — [Clover, Table 1, Fig 6-7](https://arxiv.org/abs/2405.00263)
- Clover-2: 5 RNN-style heads, 2-layer augmenting block (initialised from the last trunk layer), attention decoder fusing last hidden state with the just-sampled token embedding, hidden-state distillation (Smooth-L1 on features, weight 10, + CE to base-model probabilities, per-head decay 0.7). Frozen trunk; ShareGPT 68k dialogues, 20 epochs; compute and parameter count not stated. — [Clover-2, Sec 3-4](https://arxiv.org/abs/2408.00264)
- Clover-2 results (Spec-Bench, EAGLE's engine and tree): Vicuna-7B T=0 MT-Bench 3.00x vs EAGLE-1 2.94x, GSM8K 3.09x vs 2.94x; Llama3-8B MT-Bench 2.47x vs 2.32x; at T=1 Vicuna-7B MT-Bench 2.25x vs 2.19x. Versus Clover-1 on Vicuna-7B MT-Bench: 3.00x vs 2.27x. Ablation gains in extra tokens/step: distillation +9%, 2-layer augmenting block +9%, extraction order +7%, projector +5%. — [Clover-2, Tables 1-2, Sec 4.3](https://arxiv.org/abs/2408.00264)

**Kangaroo (Huawei)**
- Not a multi-token head: the draft model is the trunk's first l layers (l = 2 for Vicuna-7B, 3 for 13B) + a trained adapter (one multi-head attention + two norms, no FFN) + the trunk's own LM head; drafts autoregressively with confidence-based early stop, remaining layers verify. 67M added parameters versus Medusa's 591M. Frozen trunk; ShareGPT, 10 epochs, distilled to the target distribution; training compute not stated. — [Kangaroo, Sec 3-4](https://arxiv.org/abs/2404.18911)
- Results (Spec-Bench, V100 GPUs): Vicuna-7B average 1.50x (MT-Bench 1.68x) versus Medusa 1.41x, REST 1.43x, Lookahead 1.29x; Vicuna-13B 1.44x versus Medusa 1.34x. Adapter ablation: attention-only + shared LM head 67M -> 1.50x; own LM head 198M -> 1.44x; full 1-layer transformer 202M -> 1.37x; MLP-only 165M -> 1.22x. Lossless (greedy). — [Kangaroo, Tables 1-2](https://arxiv.org/abs/2404.18911)

**Amphista (AMD)**
- Architecture: 4 parallel (non-autoregressive) heads that interact through one bi-directional self-attention layer ("auto-embedding block"), fed by two trainable causal transformer layers ("staged adaptation layers") stacked on the frozen trunk; these take [h_t; embedding of the just-sampled token]. Separate LM head per position. Frozen trunk; ShareGPT, 4 epochs; loss mixes CE to target-model logits and to ground truth; training compute and parameter count not stated. — [Amphista, Sec 3-4](https://arxiv.org/abs/2406.13170)
- Results (A100-40G, greedy, Spec-Bench average / MT-Bench): Vicuna-7B Amphista 2.13x / 2.44x, Hydra++ 2.03x / 2.37x, Medusa 1.50x / 1.87x, SpS 1.45x / 1.62x, Lookahead 1.27x / 1.44x; Vicuna-33B Amphista 2.40x / 2.75x, Hydra++ 2.17x / 2.54x, Medusa 1.73x / 1.97x. With EAGLE-1 on Vicuna-7B: EAGLE 2.21x average (accepted length 3.32), Amphista 2.13x (2.98), Amphista-alpha (2 attention layers) 2.27x (3.09). Removing the staged adaptation layers is the largest single loss (2.44x -> 2.14x MT-Bench). Batch 1 -> 8: 2.32x -> 2.06x. — [Amphista, Tables 1, 4-6, 9](https://arxiv.org/abs/2406.13170)

**ProPD**
- No new head: built on Medusa heads, adds early pruning of tree branches (an early-prediction head after layer 4, top-50) and dynamic tree sizing. Training data/compute not stated. Speedup vs autoregressive: Vicuna-7B 1.95x (bs=1) to 1.39x (bs=16); 13B 1.67x; 33B 1.86x. Gain over plain Medusa is only 1.04x at bs=1 but 3.28x at bs=16. Greedy, lossless. — [ProPD, Tables 1, 3](https://arxiv.org/abs/2402.13485)

**Other retrofits found**
- Falcon (AAAI 2025): semi-autoregressive EAGLE-style head (2 LSTM layers + relaxed-causal attention + MLP, "equivalent to just two Transformer blocks") predicting k=2 tokens per head pass, trained with glancing distillation on ShareGPT 68k, "within two days on an H800 server". Vicuna-7B MT-Bench 3.10x versus EAGLE-1 2.82x and Medusa 2.06x; acceptance rate 77.6% vs 74.6% vs 60.5%. Raising k to 3 or 4 lowers acceptance (72.2%, 70.8%) and speedup. — [Falcon, Tables 1-5](https://arxiv.org/abs/2412.12639)
- BiTA: frozen base, trainable mask-token embeddings plus deep prefix prompts (about 0.06% of parameters for a 7B model), ~150k self-generated samples, about 7 hours on 4 servers x 8 A800 for a 7B model. Lossless greedy speedups 2.1-3.3x (LLaMA-2-7B MT-Bench 2.38x, LLaMA-2-70B 2.72x). — [BiTA, Tables 1-3](https://arxiv.org/abs/2401.12522)
- "Your LLM Knows the Future" (Apple, 2025): k=8 mask tokens appended, gated LoRA rank 128 active only at mask positions (so next-token outputs are bit-identical), plus a 2-block MLP "sampler head" that conditions on the previously sampled token's embedding. Tulu3-8B, ~1M Tulu3 examples, 50k iterations on 8 A100s. Tokens per step (not wall-clock): 1.54 (MMLU) to 1.86 (HumanEval) with 1 mask; average 3.17 and up to 5.35 (HumanEval) with 8 masks and quadratic decoding. No wall-clock numbers, no baselines. — [Apple, Table 1](https://arxiv.org/abs/2507.11851)
- Speculative Streaming (Apple, 2024): replaces attention in the top N_s layers with multi-stream attention, jointly fine-tunes the base with LoRA on next-token + future-token loss (weights 1 and 0.1) per downstream task; 4.1e4-8.2e4 extra parameters versus Medusa's 4.3e8-5.9e8. Speedup 1.8-3.1x on SQL / summarisation / E2E-NLG; roughly equal to Medusa (e.g. OpenLlama-7B SQL 3.14x vs 3.20x). Lossless only relative to the fine-tuned model. — [Speculative Streaming, Table 1](https://arxiv.org/abs/2402.11131)
- Medusa heads on frozen openPangu-7B (2026): head-1 / head-2 top-1 accuracy 62.4% / 42.0% (2k samples), 67.8% / 49.3% (10k, self-distilled), 74.6% / 54.1% (50k, self-distilled, special tokens kept); 65.7 training hours for the last; 1.65-1.78 tokens per step, 1.35x on an Ascend NPU at 128 tokens, falling below 1x at 1024 tokens. — [OpenPangu, Table 2, Sec 4.3](https://arxiv.org/abs/2603.03383)
- PARD (AMD): not a head. Fine-tunes an existing small same-family LM (Llama3.2-1B, Qwen2.5-0.5B) with mask tokens to emit all draft tokens in one pass; target untouched; 8x MI250X, 4 epochs. vLLM, A100-40GB: Llama3.1-8B average 3.00x versus EAGLE-3 2.65x and EAGLE-1 1.58x; Qwen2.5-7B 3.18x; first-token acceptance 0.93 (PARD) vs 0.87 (EAGLE-3) on HumanEval. Speedup collapses with batch size (3.63x at bs=1 to 1.33x at bs=16). — [PARD, Tables 1, 2, 5](https://arxiv.org/abs/2504.18583)
- AdaMTP (Aug 2026): Medusa-style MLP heads on Llama-3.1-8B / Qwen2.5-7B / Gemma-3-12B, stage 1 frozen-trunk head warm-up, stage 2 joint LoRA (rank 32, lambda = 0.1), with entropy-adaptive masking of the MTP loss. Speedup 1.43-2.75x; no acceptance rates and no comparison to Medusa/EAGLE. — [AdaMTP, Tables 1-2](https://arxiv.org/abs/2608.00434)
- AngelSpec (Tencent, July 2026): open-source training framework; its MTP drafter is exactly the DeepSeek/Qwen block (RMSNorm on hidden state and on token embedding, concat, linear projection, one transformer layer, shared embedding and LM head), trained with the target "frozen" and inputs "detached", unrolled recursively on its own predictions. On Qwen3-8B (T=1, non-thinking), mean acceptance length: MTP (1 layer) 3.24, DFlash (5 layers) 4.57, DSpark (5 layers) 5.32, DFly (5 layers) 5.41. — [AngelSpec, Sec 2, Table 3](https://arxiv.org/abs/2607.25852)

### Inferences
- Design features that repeatedly pay off across independent papers: (1) condition each draft step on the embedding of the previous draft token (Hydra, Clover, Falcon, EAGLE, the native MTP block); (2) add at least one trainable attention layer on top of the frozen trunk rather than MLPs only (Hydra++ prefix layer, Clover augmenting block, Amphista adaptation layers); (3) share the base model's LM head instead of training new vocabulary projections (Kangaroo's ablation, Clover); (4) distil from the base model's own outputs rather than ground-truth text (Hydra++, Clover-2, Kangaroo, self-distillation in Medusa, BiTA, OpenPangu). The DeepSeek/Qwen MTP block has all of (1)-(3) by construction.
- Training cost for these heads is small: published figures range from 5 A100-hours (Medusa-1) to about two days on one multi-GPU server (Falcon). Data is typically 60-70k ShareGPT dialogues, or 150k-400k self-generated samples.
- None of the head papers in this section reports results on Qwen3-8B except AngelSpec, and none except Medusa compares frozen with joint training.

### Gaps
- Absolute added-parameter counts are stated only for Clover, Kangaroo (and Medusa via Kangaroo). Training hours are missing for Hydra, Clover-2, Amphista and ProPD.
- AngelSpec does not state the Qwen3-8B MTP head's parameter count, initialisation, dataset size, GPU-hours, per-position acceptance or wall-clock speedup, and does not compare against EAGLE-3.
- I did not find a Spec-Bench-style third-party measurement of Clover, Clover-2, Amphista, Falcon or BiTA; their numbers are self-reported.

## 2. Training-free and self-speculative approaches, and classic small-draft-model speculative decoding

### Takeaway
Training-free methods mostly land at 1.1-1.7x on general chat workloads, with two exceptions: Token Recycling reaches about 2.0x on Vicuna-7B with a 2 MB lookup matrix, and copy-heavy tasks let prompt lookup reach 2.4-2.6x. Trained heads sit at roughly 2.0-3.0x on the same benchmark, so the gap bought by training is on the order of 0.5-1.0x of baseline throughput, and it narrows or reverses on weaker hardware.

### Cited Findings
- Leviathan et al.: small off-the-shelf draft model, accept with probability min(1, p/q), provably distribution-preserving. T5-XXL (11B) with T5-small (77M): 3.4x (EnDe, T=0), 3.1x (CNN/DM, T=0), 2.6x / 2.3x at T=1; acceptance rate 0.75 / 0.65 at T=0. Larger drafters are worse (T5-large 1.7x). Expected tokens per target call = (1 - a^(g+1)) / (1 - a). — [Leviathan et al., Tables 2-4](https://arxiv.org/abs/2211.17192)
- Chen et al.: Chinchilla 70B with a purpose-trained 4B, 8-layer draft model (1.8 ms/token vs 14.1): 1.92x (XSum nucleus), 2.01x (XSum greedy), 2.46x (HumanEval), K = 4. — [Chen et al., Table 1](https://arxiv.org/abs/2302.01318)
- Draft & Verify (Self-SD): the draft is the same model with a fixed subset of attention/MLP sub-layers skipped, chosen by offline Bayesian optimisation (about 2.5 h for 13B, 6 h for 70B; SWIFT re-measured 7.5 h and 20 h on an A6000). Lossless. 1.21-1.99x (LLaMA-2-13B CNN/DM 1.57x; LLaMA-2-70B 1.99x; MT-Bench 13B-Chat 1.27x). — [Draft & Verify, Tables 1, 13, App B](https://arxiv.org/abs/2309.08168)
- LayerSkip: requires training the base model itself with layer dropout and an early-exit loss (e.g. continual pretraining on 52B tokens, 50k steps on 64 A100s), then early-exit drafting with the remaining layers verifying. 1.34-2.16x (Llama2-7B CNN/DM 1.86x). Lossless only with respect to the retrained model. — [LayerSkip, Tables 3-4, 8](https://arxiv.org/abs/2404.16710)
- SWIFT: layer-skipping set optimised on the fly during inference (about 2 minutes), no training. 1.3-1.6x on LLaMA-2 13B/70B (overall 1.41x / 1.48x) versus Lookahead 1.26-1.29x. Under the same harness: LayerSkip 1.64x, Self-SD 1.29x, SWIFT 1.56x (LLaMA-2-13B CNN/DM). Self-SD drops from 1.33x to about 1.05x under domain shift. — [SWIFT, Tables 2, 10-12, Fig 7](https://arxiv.org/abs/2410.06916)
- REST: retrieval from a 12-27 GB suffix-array datastore, no model training. 1.69x / 1.77x on MT-Bench (Vicuna 7B/13B), 2.36x / 2.27x on HumanEval (CodeLlama 7B/13B); speedup grows with datastore size (0.9 GB 1.83x to 27 GB 2.36x). — [REST, Tables 1-2](https://arxiv.org/abs/2311.08252)
- Token Recycling: stores the top-8 next-token candidates per vocabulary token from previous steps in a <2 MB matrix and builds a draft tree from it. Own A100 runs on Spec-Bench: Vicuna-7B 2.03x (MAT 2.70) versus Medusa-1 1.65x, PLD 1.53x, Lookahead 1.27x, REST 1.22x; 13B 1.89x; 33B 1.91x; MBPP 2.34x. Versus EAGLE: TR 2.09x, EAGLE-1 2.08x, EAGLE-2 2.28x. — [Token Recycling, Tables 1, 2, 5](https://arxiv.org/abs/2408.08696)
- Prompt lookup decoding (PLD) and Lookahead on Spec-Bench Vicuna-7B: PLD 1.62x (3090) / 1.66x (A100), reaching 2.41x-2.59x on summarisation but 1.06-1.11x on translation; Lookahead 1.11x (3090) / 1.77x (A100). — [Spec-Bench paper, Tables 5-6](https://arxiv.org/abs/2401.07851)
- ESP (training-free mask-embedding probing, ICML 2026) on Qwen3-8B, the reader's target: tau 1.63-1.74 and 1.37-1.43x; PLD 1.12x; on Llama-3.1-8B ESP 1.35-1.38x versus EAGLE-3 2.36-2.61x. The paper puts EAGLE-3 training at "200-300 GPU hours". — [ESP, Tables 1, 10](https://arxiv.org/abs/2603.17942)
- A separate small Qwen3 drafter in stock vLLM carries heavy orchestration overhead: Qwen3-0.6B costs 5.19 ms/token standalone but 16.54 ms/token inside vLLM speculative decoding against a 19.53 ms/token Qwen3-32B verifier (relative cost 0.85 instead of 0.27). — [Relaxed SD investigation, Table 1](https://arxiv.org/abs/2607.08690)

### Inferences
- For Qwen3-8B specifically, the training-free floor is about 1.4x (ESP) and the published trained-head ceiling on a comparable 8B model is about 2.4-2.7x (EAGLE-3 on Llama-3.1-8B per ESP and PARD). A retrofitted single-layer MTP block should be judged against that band.
- Classic two-model speculative decoding is attractive on paper (PARD: 3.0x on Llama3.1-8B) but depends on a well-matched small sibling model and loses most of its gain to framework overhead and batching.

### Gaps
- No source gives PLD, REST or Token Recycling numbers on Qwen3-8B other than ESP's PLD figure.
- Spec-Bench did not benchmark LayerSkip, Self-SD, SWIFT or Kangaroo; their cross-method comparisons come only from SWIFT's and Kangaroo's own tables.

## 3. Independent head-to-head comparisons

### Takeaway
Spec-Bench is still the only widely used neutral benchmark; its ranking on Vicuna is EAGLE family > Hydra > Token Recycling ~ Medusa > SpS ~ PLD > REST > Lookahead, with trained heads at about 1.7-2.7x and training-free methods at about 1.1-2.2x depending on GPU. Rankings shift with hardware, precision and temperature, and no neutral benchmark covering Qwen3 or the native MTP modules was found.

### Cited Findings
- Spec-Bench design: 6 subtasks x 80 samples (MT-Bench, WMT14 DE-EN, CNN/DM, Natural Questions QA, GSM8K, NQ-RAG), Vicuna-v1.3 7B/13B/33B, batch 1, FP16, mean of 3 runs. — [Spec-Bench paper, Sec 8, App B](https://arxiv.org/abs/2401.07851)
- Paper, Vicuna-7B, RTX 3090, T=0, overall: EAGLE 2.08x, SpS (68M drafter) 1.77x, PLD 1.62x, Medusa 1.48x, REST 1.39x, Lookahead 1.11x. At T=1: EAGLE 1.74x, SpS 1.49x, REST 1.35x. — [Spec-Bench paper, Table 5](https://arxiv.org/abs/2401.07851)
- Paper, A100, T=0: Vicuna-7B Medusa 2.42x, EAGLE 2.39x, Lookahead 1.77x, PLD 1.66x, SpS 1.59x, REST 1.59x; Vicuna-13B EAGLE 2.53x, Medusa 2.16x; Vicuna-33B EAGLE 2.50x, Medusa 2.01x. In FP32 on the A100, EAGLE falls to 1.74x, Medusa to 1.72x and PLD to 1.01x. The paper notes FP16 speculative outputs "may not consistently align" with autoregressive outputs; FP32 is exact. — [Spec-Bench paper, Table 6, Fig 10, App D.3](https://arxiv.org/abs/2401.07851)

- The same method measured by different papers (Medusa-1, Vicuna-7B, MT-Bench, greedy): 2.18x (Medusa's own), 2.13x (Hydra, A100-40GB), 1.87x (Amphista, A100-40G), 1.55x (Kangaroo, V100). — [Medusa](https://arxiv.org/abs/2401.10774); [Hydra](https://arxiv.org/abs/2402.05109); [Amphista](https://arxiv.org/abs/2406.13170); [Kangaroo](https://arxiv.org/abs/2404.18911)

### Inferences
- On Spec-Bench the gap between the best non-EAGLE head (Hydra, 2.07x on A100 Vicuna-7B) and EAGLE-2 (2.36x) is modest, and a training-free method (Token Recycling, 2.22x) sits between them on the A100, while collapsing to 1.40x on the 3090. Hardware and implementation move results as much as the method does.
- A single-layer MTP block is a weaker drafter per step than 5-layer diffusion-style drafters, but its low cost makes it competitive at high concurrency, which matches vLLM's documentation that MTP mainly helps latency at low concurrency.

### Gaps
- No neutral benchmark was found that puts Medusa, Hydra, EAGLE-3 and a native or retrofitted MTP block on the same Qwen3-family model and hardware.
- The Spec-Bench leaderboard has no entries for Clover-2, Amphista, Kangaroo, Falcon, PARD or any MTP module. The leaderboard page carries no date.

## 4. Natively trained MTP

### Takeaway
All shipped MTP modules (DeepSeek-V3, MiMo, Qwen3-Next/3.5, Nemotron 3, Step 3.5 Flash, Hy3) are one light transformer block co-trained with the trunk from pretraining with an auxiliary loss weight of 0.1-0.3, and all deliver about 80-90% acceptance on the first drafted token. Used recursively without extra work they collapse at depth 2-3 (MiMo: 70% / 10% / ~0%; Hy3: 80% / 52% / 27% cumulative); the vendors who get deep drafts (Qwen "trained with multi-steps", NVIDIA shared-weight heads plus "boosting", Tencent TTT) fix this with recursive training, and that fix is done with the trunk frozen.

### Cited Findings

**DeepSeek-V3**
- Module k: shared embedding, shared output head, its own transformer block TRM_k and projection M_k (d x 2d). Input `h'_i = M_k [RMSNorm(h^{k-1}_i); RMSNorm(Emb(t_{i+k}))]`; modules are chained sequentially and keep "the complete causal chain at each prediction depth". — [DeepSeek-V3, Sec 2.2, Eq 21-23](https://arxiv.org/abs/2412.19437)
- Depth D = 1. Loss L_MTP = (lambda / D) * sum_k CE_k added to the main loss; "The MTP loss weight λ is set to 0.3 for the first 10T tokens, and to 0.1 for the remaining 4.8T tokens." — [DeepSeek-V3, Sec 4.2, Eq 24-25](https://arxiv.org/abs/2412.19437)
- Stated purpose is training signal: "Our MTP strategy mainly aims to improve the performance of the main model, so during inference, we can directly discard the MTP modules"; they "can also repurpose these MTP modules for speculative decoding". — [DeepSeek-V3, Sec 2.2](https://arxiv.org/abs/2412.19437)
- Ablation with the module discarded at inference: small MoE (15.7B, 1.33T tokens) HumanEval 20.7 -> 26.8, GSM8K 25.4 -> 31.4, MMLU 50.0 -> 53.3; large MoE (228.7B, 540B tokens) HumanEval 44.5 -> 53.7, DROP 68.5 -> 70.6, MMLU 67.5 -> 66.6. — [DeepSeek-V3, Table 4](https://arxiv.org/abs/2412.19437)
- "the acceptance rate of the second token prediction ranges between 85% and 90% across various generation topics ... delivering 1.8 times TPS". Hardware and method are not given; MTP parameter count is not stated. — [DeepSeek-V3, Sec 5.4.3](https://arxiv.org/abs/2412.19437)
- Third-party measurement in SGLang (2 nodes, 16 H200, 2 concurrent requests): baseline 51.0 tok/s per rank, MTP with a 3-token window 81.5 (+59.8%, average acceptance length 2.18), 4-token window 82.0 (+60.8%, 2.44); at 128 concurrent requests only +14.2%. — [LMSYS/SGLang blog, July 2025](https://www.lmsys.org/blog/2025-07-17-mtp)
- On SPEED-Bench at draft length 7 the DeepSeek heads are the weakest native ones: DeepSeek-R1 2.70, DeepSeek-V4-Flash 2.67 average acceptance length. — [Nemotron 3 Super report, Table 2](https://research.nvidia.com/labs/nemotron/files/NVIDIA-Nemotron-3-Super-Technical-Report.pdf); [Nemotron 3 Ultra, Table 6](https://arxiv.org/abs/2606.15007)

**Qwen3-Next and Qwen3.5**
- Qwen3-Next model card: "Multi-Token Prediction (MTP): Boosts pretraining model performance and accelerates inference." Recommended serving: SGLang `--speculative-algo NEXTN --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4`; vLLM `{"method":"qwen3_next_mtp","num_speculative_tokens":2}`. — [Qwen3-Next-80B-A3B-Instruct model card](https://huggingface.co/Qwen/Qwen3-Next-80B-A3B-Instruct)
- Qwen3-Next blog: a "native Multi-Token Prediction (MTP) mechanism, which not only yields an MTP module with a high acceptance rate for Speculative Decoding but also enhances the overall performance", and it "specifically optimizes the multi-step inference performance of MTP, further improving the acceptance rate of Speculative Decoding in real scenarios through multi-step training that maintains consistency between training and inference." No acceptance or speedup number is given. Trained on 15T tokens. — [Alibaba Cloud blog](https://www.alibabacloud.com/blog/qwen3-next-towards-ultimate-training-%26-inference-efficiency_602580)
- Qwen3.5-9B model card: the only description is "MTP: trained with multi-steps"; 32 layers, hidden 4096, FFN 12288; same SGLang/vLLM commands. Config: `mtp_num_hidden_layers: 1`, `mtp_use_dedicated_embeddings: false`, 16 attention heads, 4 KV heads, head_dim 256. — [Qwen3.5-9B model card](https://huggingface.co/Qwen/Qwen3.5-9B); [config.json](https://huggingface.co/Qwen/Qwen3.5-9B/raw/main/config.json)
- Architecture as implemented: `pre_fc_norm_hidden` on the trunk hidden state, `pre_fc_norm_embedding` on the next-token embedding, linear fusion `mtp.fc`, one full-attention decoder layer, shared `lm_head`; the head keeps its own KV cache. — [mlx-lm PR #990](https://github.com/ml-explore/mlx-lm/pull/990); [graft-mtp README](https://github.com/MH221B/graft-mtp)
- Measured acceptance for Qwen3.5/3.6 native heads (community, not official): Qwen3.6-27B 4-bit on M4 Pro, depth 1: 88.3% at T=0 (1.57x), 84.8% at T=0.6, 80.5% at T=1.0; Qwen3.5-4B in llama.cpp at T=0.7: 88.8% / 82.6% / 72.5% average acceptance at draft depth 1 / 2 / 3, 1.49x at depth 2; Qwen3.5-9B via vLLM speculators after domain fine-tuning: per-position 89.4% / 72.3% / 61.7% (3 prompts only). — [mlx-lm PR #990](https://github.com/ml-explore/mlx-lm/pull/990); [graft-mtp README](https://github.com/MH221B/graft-mtp); [speculators example script](https://github.com/vllm-project/speculators/blob/main/examples/train/mtp_qwen3_5_9b_gsm8k_online.sh)
- Qwen3.5-27B native MTP under strict (lossless) verification, thinking mode, T=0.6, AIME24: mean accepted draft tokens (excluding bonus) 2.44 / 3.52 / 4.82 / 5.36 at draft length 3 / 5 / 10 / 20; a separate Qwen3-0.6B drafter for Qwen3-32B gets 2.14 / 3.05 / 4.32 / 5.25 and a Qwen3-8B drafter 2.46 / 3.72 / 5.94 / 8.15. — [Relaxed SD investigation, Table 3](https://arxiv.org/abs/2607.08690)
- vLLM guidance: "MTP-1 reduces time-per-output-token (TPOT) with a high acceptance rate, at the cost of lower throughput under load"; `num_speculative_tokens` adjustable 1-5. — [vLLM Qwen3.5 recipe](https://docs.vllm.ai/projects/recipes/en/latest/Qwen/Qwen3.5.html)
- Community throughput on an A100 for Qwen3.5-9B BF16: 83 tok/s without MTP, 104 with k=1, 198 with k=3 (2.4x). — [alityb/Qwen3.5-9B-FullINT4-MTP model card](https://huggingface.co/alityb/Qwen3.5-9B-FullINT4-MTP)

**MiMo-7B (measured by FastMTP)**
- MiMo-7B-RL: 36 layers, single-layer DeepSeek-style MTP module, 210.8M parameters (under 3% of 7,833.4M). Native head used recursively: acceptance about 70% at step 1, 10% at step 2, near zero at step 3; speedup 1.32x at K=1 and 1.21x at K=3 (A10 GPU, SGLang, greedy). — [FastMTP, Sec 3.1, 3.4, Table 1](https://arxiv.org/abs/2509.18362)

**NVIDIA Nemotron 3 Super / Ultra**
- Two MTP layers with shared weights (one attention layer + one MoE layer), co-trained during pretraining with loss weight 0.3 (Super) or 0.1 (Ultra), kept during SFT. Motivation: reusing one head recursively "introduces a training-inference mismatch: the head is trained under ground-truth hidden states but, at inference, conditions on its own generated states." — [Nemotron 3 Super report, Sec 2.1.2, 2.4](https://research.nvidia.com/labs/nemotron/files/NVIDIA-Nemotron-3-Super-Technical-Report.pdf); [Nemotron 3 Ultra, Sec 2.1, 2.4](https://arxiv.org/abs/2606.15007)
- Super "MTP healing" stage: "we train the MTP heads and keep rest of the weights frozen ... using the negative log likelihood loss ... on the generated responses. We find this stage significantly improves MTP accuracy." No numbers. — [Nemotron 3 Super report, Sec 3.2](https://research.nvidia.com/labs/nemotron/files/NVIDIA-Nemotron-3-Super-Technical-Report.pdf)
- Ultra "MTP boosting": backbone frozen, only the head trained for 12K steps at batch 64 on on-policy rollouts (<= 8K tokens), forward-KL to the backbone's logits at temperature 2 over 7 recursive steps, with step-k inputs sampled from earlier MTP steps' hidden states. Average acceptance length 4.387 -> 4.584 (greedy), speedup gains 3.15-5.82%. Single-user throughput peaks at draft length 6 with 2.89x. — [Nemotron 3 Ultra, Sec 3.4, 5, Table 6](https://arxiv.org/abs/2606.15007)

**Step 3.5 Flash, Hy3, Gemma 4**
- Step 3.5 Flash: three MTP heads (sliding-window attention + dense FFN, "0.81B parameters (~0.41%)"); "we activate and optimize only MTP-1 in most training stages. Once the backbone is well-trained, we initialize MTP-2 and MTP-3 from MTP-1 and jointly train all MTP heads in a lightweight post-training phase." Loss weight 0.3 then 0.1. No acceptance numbers. — [Step 3.5 Flash, Sec 2.1-2.2](https://arxiv.org/abs/2602.10604)
- Hy3: "trained with a single MTP layer and without recurrent self-conditioned unrolling". Cumulative per-position acceptance of the native head at T=0: 0.799 / 0.518 / 0.266; after frozen-trunk recursive post-training on target rollouts: 0.814 / 0.653 / 0.524 (mean accepted length 2.58 -> 2.99). — [AngelSpec, Sec 2, Table 2](https://arxiv.org/abs/2607.25852)
- Gemma 4: "We train a small autoregressive MTP drafter head with our models"; a separate embedder plus a 4-layer transformer that cross-attends to the main model's KV cache; width 256 (E2B/E4B) or 1024 (26B/31B); 76M-500M parameters. No acceptance or speedup numbers, and training details are not given. — [Gemma 4 Technical Report, Sec 2.6, Table 1](https://arxiv.org/abs/2607.02770)

**Earlier work**
- Gloeckle et al. 2024: shared trunk, n parallel heads each one transformer layer, shared unembedding; heads do not see intermediate tokens. Trained from scratch (0.3B-13B, >= 91B code tokens). 13B solves 12% more HumanEval and 17% more MBPP problems; MTP hurts below about 1.3B parameters. Self-speculative decoding with the 7B 4-token model: 3.0x on code with "2.5 accepted tokens out of 3 suggestions", 2.7x on text; with only the first extra head, 1.85x (code) and 1.79x (Wikipedia), i.e. about 94% and 88% acceptance (derived). — [Gloeckle et al., Sec 3, Tables S2, S7](https://arxiv.org/abs/2404.19737)
- ProphetNet: future n-gram prediction with n-stream self-attention in a seq2seq pretraining setup; the extra streams are disabled at inference ("we can easily convert the ProphetNet decoder to the traditional Transformer decoder by disabling all the predicting streams"). Used for quality, not speed. — [ProphetNet](https://arxiv.org/abs/2001.04063)
- At small scale co-trained MTP costs next-token quality: 1.3B / 3B models trained from scratch get worse bits-per-byte with 2 or 4 heads (1.08 -> 1.18-1.19 at 1.3B with 4 heads). — [Pre-Training Curriculum for MTP, Table 1](https://arxiv.org/abs/2505.22757)

**Is the trunk co-trained or frozen in the Qwen models?**
- Official wording implies co-training during pretraining for Qwen3-Next ("Boosts pretraining model performance"; the mechanism "also enhances the overall performance"). — [Qwen3-Next model card](https://huggingface.co/Qwen/Qwen3-Next-80B-A3B-Instruct); [Alibaba Cloud blog](https://www.alibabacloud.com/blog/qwen3-next-towards-ultimate-training-%26-inference-efficiency_602580)
- For Qwen3.5 the only official statement is "MTP: trained with multi-steps". A community model card says the head "was trained alongside the model" and an mlx-lm commit message says "The MTP head was trained with full prefix context", but neither is from the Qwen team. — [Qwen3.5-9B model card](https://huggingface.co/Qwen/Qwen3.5-9B); [alityb model card](https://huggingface.co/alityb/Qwen3.5-9B-FullINT4-MTP); [mlx-lm PR #990](https://github.com/ml-explore/mlx-lm/pull/990)

### Inferences
- Parameter count of the Qwen3.5-9B MTP block computed from its config (one full-attention layer with 16 Q heads and 4 KV heads of dim 256, SwiGLU FFN 3 x 4096 x 12288, fusion 8192 x 4096): about 42M + 151M + 34M = roughly 227M (derived, not stated anywhere). This is consistent with MiMo-7B's stated 210.8M for the same hidden size. The ~120M figure in the brief would correspond to a smaller hidden size, such as a 4B-class model; I could not confirm a published count for any Qwen3.5 size.
- "Trained with multi-steps" most plausibly means the same thing NVIDIA, Tencent and FastMTP describe: the single block is unrolled recursively for several steps during training so that step-k inputs match inference. Whether Qwen does this during pretraining with the trunk receiving gradients, or in a post-hoc frozen-trunk stage, is not disclosed.
- The first-token acceptance of a native head (roughly 80-90%) is a property of co-training at pretraining; deep-draft acceptance (positions 2+) in every documented case was obtained or substantially improved by head-only training with the trunk frozen (FastMTP, Hy3 TTT, Nemotron healing/boosting, vLLM speculators).

### Gaps
- No Qwen technical report describing the MTP loss weight, schedule, number of unroll steps, or whether the trunk is frozen during multi-step training was found. Official acceptance rates for Qwen3-Next and Qwen3.5 are not published.
- DeepSeek's 1.8x TPS and 85-90% figures come without hardware or methodology.
- Gemma 4 and Step 3.5 Flash publish no MTP acceptance or speedup figures.

## 5. Frozen trunk versus joint training

### Takeaway
There is still no clean experiment comparing a natively co-trained MTP block with the same block trained post hoc on the frozen trunk of the same model. The available evidence says: a frozen trunk loses real acceptance (Mehra et al.: second-token top-5 accuracy 0.50-0.61 frozen versus 0.54-0.67 joint versus 0.68-0.78 for the marginalisation upper bound; Medusa: 2.18x frozen versus 2.83x joint), but the loss is concentrated in parallel heads that do not see the intermediate token, and joint training on an already pretrained model routinely damages the model (Medusa direct fine-tuning, Gloeckle's Llama 2, AdaMTP's standard MTP, GrowMTP's joint arm collapsing to zero accuracy). The two published frozen-trunk retrofits of a Qwen-style block reach roughly the acceptance length of native heads at short draft lengths (Qwen3-8B 3.24; Qwen3-4B 2.9 in-domain, 2.1-2.3 held-out).

### Cited Findings

**Direct frozen-versus-joint numbers**
- Medusa, Vicuna-7B: Medusa-1 (frozen) 2.18x, quality 6.23; Medusa-2 (joint, LoRA) 2.83x, quality 6.18; baseline quality 6.17; naive joint fine-tuning with heads 5.925. Vicuna-13B: 2.33x -> 2.83x with quality -0.14. Reason given: "at the beginning of training, the MEDUSA heads have a large loss, which leads to a large gradient and may distort the backbone model's parameters", and "in MEDUSA-1, the full potential of the backbone model is not utilized." — [Medusa, Table 2, Fig 3a, Sec 2.2](https://arxiv.org/abs/2401.10774)
- Mehra et al. (Sony/EPFL, 2025) replicate the final transformer layer as a second head on Pythia models and train on translation. Top-5 accuracy of the 2nd token (410M / 1B / 1.4B / 2.8B): heads only, frozen backbone 0.500 / 0.590 / 0.573 / 0.607; vanilla joint (LoRA r=8) 0.538 / 0.603 / 0.608 / 0.645; best joint variant (differential LR + weighted hidden states or head warm-up) 0.590 / 0.623 / 0.642 / 0.667; marginalisation baseline from the fine-tuned NTP model 0.682 / 0.730 / 0.760 / 0.777. Joint training lowered next-token top-5 accuracy (e.g. 0.856 -> 0.828-0.839 at 2.8B). — [Mehra et al., Table 1](https://arxiv.org/abs/2502.09419)
- Their conclusion: hidden layers "are strongly specialized for NTP, making adaptation non-trivial"; joint training "cannot fully overcome this barrier"; "training the strongest MTP models likely requires full MTP pretraining", yet "MTP adaptation remains useful in scenarios requiring only rough token drafts (e.g., self-speculative decoding)." Their heads are parallel (no next-token embedding input). — [Mehra et al., Abstract, Sec 3-4](https://arxiv.org/abs/2502.09419)
- GrowMTP (Sept 2026), Qwen3.5-4B native head during RL fine-tuning: frozen head tau 2.65; head trained with detached backbone states tau 3.18-3.22 with quality preserved; joint CE training reached tau 3.99 but "its held-out quality is zero in both domains". — [GrowMTP, Tables 3, 8](https://arxiv.org/abs/2609.16648)

**Joint training of a pretrained model with an MTP loss tends to hurt the model**
- Gloeckle et al.: "Finetuning LLama 2 with multi-token prediction does not significantly improve performance ... We suppose that this new loss changes the initialization too brutally and never really recovers." HumanEval pass@1 31.4 (n=1) versus 27.9-29.0 (n=4 variants) after 200B code tokens. They also assert, without numbers: "Pretraining with multi-token prediction allows the additional heads to be much more accurate than a simple finetuning of a next-token prediction model". — [Gloeckle et al., App D Table S6, Sec 3.2](https://arxiv.org/abs/2404.19737)
- AdaMTP: "Standard MTP consistently underperforms NTP on average across all three models" when the backbone is LoRA-tuned with Medusa-style heads (e.g. Llama-3.1-8B 35.90 vs 36.32). — [AdaMTP, Table 1](https://arxiv.org/abs/2608.00434)
- Apple gated-LoRA paper: with ordinary (ungated) LoRA, next-token loss rises and ARC accuracy "drop[s] sharply" during MTP fine-tuning; gating the LoRA to mask positions keeps it constant. Acceptance stays reasonable even at LoRA rank 1, and "adding the sampler head has a more significant impact on acceptance rate than simply increasing the LoRA rank". — [Apple, Sec 3.1, 3.3](https://arxiv.org/abs/2507.11851)
- MuToR: Gloeckle-style heads added during fine-tuning of pretrained Gemma-2B / Llama3-8B give small or no gains and need about 110M new parameters per head on Gemma-2B; such heads "must be trained from scratch, making them less effective in fine-tuning scenarios." — [MuToR, Tables 1, 3](https://arxiv.org/abs/2505.10518)

**Frozen-trunk training of a DeepSeek/Qwen-style block**
- FastMTP: starts from MiMo-7B's native (co-trained) head, freezes everything else, fine-tunes the 210.8M-parameter head with weights shared across K=3 recursive steps (loss weights 0.51 / 0.31 / 0.18 from beta = 0.6) on 389.4K self-distilled English/Chinese samples, "less than 1 day on a single H20 server". Acceptance 70% -> 81% (step 1), 11% -> 56% (step 2), 2% -> 36% (step 3); speedup at K=3 from 1.21x to 1.81x, 2.03x with vocabulary compression; self-distilled data beats fixed data (1.81x vs 1.67x). — [FastMTP, Sec 2-3, Table 1](https://arxiv.org/abs/2509.18362)
- AngelSpec on Hy3: native head 0.799 / 0.518 / 0.266 cumulative acceptance -> 0.814 / 0.653 / 0.524 after frozen-backbone recursive training on target rollouts. Position 1 barely moves (+1.5 points); positions 2-3 gain 13.5 and 25.8 points. — [AngelSpec, Table 2](https://arxiv.org/abs/2607.25852)
- GrowMTP on Qwen3-4B (no native head): randomly initialised single-layer block, backbone states detached, K=5: tau 2.91 on its own math rollouts and 2.64 on code after 500 RL steps (still rising); 2.30-2.34 on held-out math benchmarks, 2.11-2.27 on held-out code, 1.45-1.75 cross-domain. An offline-trained head with the same objective on the frozen initial checkpoint reached tau 2.92 for 161.6 GPU-hours (8x H800, includes rollout generation). — [GrowMTP, Tables 1, 2, 7, 13](https://arxiv.org/abs/2609.16648)
- AngelSpec on Qwen3-8B (no native head): single-layer MTP block trained with the target frozen, 10 epochs on regenerated Open-PerfectBlend responses: mean acceptance length 3.24 (Math500 3.53, GSM8K 3.56, HumanEval 3.33, MBPP 3.22, LiveCodeBench 3.25, MT-Bench 2.57) at T=1. For comparison the post-trained native head on Hy3 scores 3.00 on the same benchmarks. — [AngelSpec, Table 3](https://arxiv.org/abs/2607.25852)

**Do frozen hidden states already encode future tokens?**
- Future Lens (GPT-J-6B): from a single hidden state, agreement with the model's own token at t+2 is 48.4% using a learned soft-prompt transplant (best at middle layers), 29.2% with a linear probe to the final hidden state, 27.5% linear-to-vocabulary, against a 20.1% bigram baseline. Accuracy reaches 95% when the model's own confidence is above 90%. The decoder is not given token t+1. — [Future Lens, Table 2](https://arxiv.org/abs/2311.04897)
- Mehra et al.: next-token-only models can do 2-token prediction by marginalising over the intermediate token, and this ability grows with model size; they also show intermediate layers converge early to the final next-token distribution in large models, which they read as information for later tokens being discarded. — [Mehra et al., Sec 2-3](https://arxiv.org/abs/2502.09419)
- ESP: probing a frozen model with synthetic mask embeddings yields essentially one extra token; tau with 1 / 2 / 3 masks is 1.73 / 1.71 / 1.57 on Llama-3.1-8B. — [ESP, Table 3](https://arxiv.org/abs/2603.17942)
- Apple: before any training, placeholder tokens put the correct future tokens "within the top 200 logits"; after mask fine-tuning, top-10. — [Apple, Sec 1](https://arxiv.org/abs/2507.11851)
- Hydra motivates its trainable prefix layer with: "as the base model is trained independently of the Hydra heads, it is not obvious whether sufficient information regarding the context is encoded in the last token's hidden state." — [Hydra, App A](https://arxiv.org/abs/2402.05109)
- Frozen-trunk Medusa heads on openPangu-7B top out at 74.6% / 54.1% top-1 for the first / second extra token. — [OpenPangu, Table 2](https://arxiv.org/abs/2603.03383)

### Inferences
- The frozen-trunk penalty is largest for heads that must guess t+2 without seeing token t+1 (Medusa, Mehra, Gloeckle heads): there the head has to recover a marginal over the intermediate token from a state specialised for next-token prediction. The DeepSeek/Qwen block is given the embedding of token t+1, which turns the task into ordinary next-token prediction from a slightly stale state plus one attention layer of capacity. This is the same reason sequentially dependent retrofits (EAGLE, Hydra, Falcon) reach 75-80% per-token acceptance on frozen trunks, compared with about 60% for Medusa.
- Expected outcome for a frozen-trunk Qwen-style block on Qwen3-8B, read off the two retrofits and the native heads: first-draft acceptance in the mid-70s to low-80s percent and an acceptance length around 3.0-3.3 at draft length 3-8 on in-distribution data, versus roughly 80-90% first-draft acceptance and 3.3-4.6 acceptance length (draft length 7) for native heads on much larger models. The comparison is confounded by model size, data and draft length; no source isolates the co-training effect.
- Practical consensus across FastMTP, AngelSpec, Nemotron and vLLM speculators: keep the trunk frozen (it guarantees losslessness and avoids the quality damage documented above), train on responses regenerated by the target model itself, unroll the block recursively on its own outputs during training with decaying per-step weights or a distillation/acceptance-based loss, and distil from the target's logits rather than gold tokens.
- If co-training matters, the documented mechanism is the trunk learning to keep information useful for later tokens in its last hidden state (DeepSeek's "pre-plan its representations"). Hydra++, Clover and Amphista compensate by adding a trainable attention layer over the frozen trunk; EAGLE-3 compensates by reading intermediate layers; Mehra's weighted-hidden-states result (best of their variants) and Future Lens's mid-layer peak both point the same way. A single-layer block fed only the final-norm hidden state does not have that option.

### Gaps
- No paper trains the same MTP block (a) jointly from pretraining and (b) post hoc on a frozen next-token-only checkpoint of the same model and compares acceptance. This is the central unanswered question.
- No source reports per-position acceptance or wall-clock speedup for a retrofitted MTP block on Qwen3-8B, or compares it against the public EAGLE-3 heads for Qwen3-8B.
- Mehra et al. is a small-model (<= 2.8B), translation-only study with parallel heads; its numbers may not transfer to a sequential block on an 8B chat model.
- GrowMTP's joint-training collapse occurred inside an RL fine-tune with a CE head loss; it does not test joint supervised fine-tuning with a small loss weight.

## 6. Has anyone publicly retrofitted a DeepSeek-style or Qwen-style MTP module onto a model that lacked one?

### Takeaway
Yes, twice in 2026, both from Tencent: AngelSpec trains the block on frozen Qwen3-8B (open-source framework, acceptance length 3.24), and GrowMTP grows it from random initialisation on Qwen3-4B inside an RL loop. Everything else public either fine-tunes an existing native head (FastMTP, vLLM speculators, NVIDIA NeMo AutoModel, Nemotron boosting), copies a native head between sibling checkpoints, or trains EAGLE-3 heads for Qwen3-8B.

### Cited Findings
- AngelSpec: "an open-source training framework for MTP and block-parallel speculative decoding", built on TorchSpec, code at github.com/Tencent/AngelSpec; its MTP drafter shares embedding and LM head with the frozen target and is trained with recursive test-time-training unrolls, an LK (negative log-overlap) cold start and an end-to-end total-variation chain loss. It reports the Qwen3-8B MTP row quoted above. Loss ablation on a small MoE target at depth 4: CE 3.80, KL 3.92, LK 3.95, TV-chain with LK cold start 3.96. — [AngelSpec, Sec 2, 6, Tables 1, 3](https://arxiv.org/abs/2607.25852)
- GrowMTP: head is "identical to the two native heads down to the parameter names" (Qwen3.5 and MiMo), one decoder layer, separate RMSNorms on hidden state and token embedding, concat, bias-free linear projection, own KV cache; "The head contains neither an embedding nor an output projection and takes both from the backbone." Random init N(0, 0.02), head LR 3e-4. Project page growmtp.github.io; no code or weights link in the paper. — [GrowMTP, App B.1](https://arxiv.org/abs/2609.16648)
- FastMTP explicitly fine-tunes an existing native head (MiMo-7B) and contains no from-scratch experiment; code at github.com/Tencent-BAC/FastMTP. — [FastMTP](https://arxiv.org/abs/2509.18362)
- vLLM speculators supports MTP only as fine-tuning of a native head: "Unlike Eagle-3, DFlash, or P-EAGLE which train draft models from scratch, MTP finetuning starts from the model's native MTP head"; "Only the MTP layers are trainable. `embed_tokens` and `lm_head` are frozen and shared with the verifier"; loss weights follow FastMTP (beta 0.6, 3 steps -> 0.51 / 0.31 / 0.18). The Qwen3.5-9B GSM8K example (5,000 samples, 3 epochs, LR 1e-4) trains in 256 seconds on one GPU. — [speculators MTP docs](https://docs.vllm.ai/projects/speculators/en/latest/user_guide/algorithms/mtp/); [example script](https://github.com/vllm-project/speculators/blob/main/examples/train/mtp_qwen3_5_9b_gsm8k_online.sh)
- NVIDIA NeMo AutoModel has a recipe that freezes everything except `*mtp*` modules for models that already ship an MTP layer (Qwen3.5, Nemotron, Step, DeepSeek-V4, GLM-5.2 and others); it does not cover adding a head to a model without one. — [NeMo AutoModel MTP guide](https://docs.nvidia.com/nemo/automodel/recipes-e2e-examples/mtp-speculative-decoding.md)
- Community "graft": copying the stock Qwen3.5-4B MTP block onto a merged/abliterated Qwen3.5-4B derivative gives 82.6% acceptance at depth 2 with no training; a 216-step realignment attempt made it worse (63.2%). — [graft-mtp README](https://github.com/MH221B/graft-mtp)
- For Qwen3-8B the public retrofit artefacts are EAGLE-3 heads, not MTP blocks: RedHatAI/Qwen3-8B-speculator.eagle3, Tengyunw/qwen3_8b_eagle3, AngelSlim/Qwen3-8B_eagle3, WhiFlash/Qwen3-8B-EAGLE3, and a multilingual variant. — [vLLM speculators EAGLE-3 docs](https://docs.vllm.ai/projects/speculators/en/latest/user_guide/algorithms/eagle3/); [SwitchXDDD multilingual head](https://huggingface.co/SwitchXDDD/multilingual-eagle3-qwen3-8b)
- Serving-side constraint: vLLM and SGLang route MTP through model-family-specific classes that consume target hidden states (`qwen3_5_mtp.py`, `MTPModelTypes`); a checkpoint whose weight names or dimensions do not match "fails with load- or run-time errors". — [Relaxed SD investigation, App H](https://arxiv.org/abs/2607.08690)
- A PR training a one-layer draft head for Qwen3-ASR on a frozen backbone (labelled EAGLE-3 in the vLLM `EagleLlamaForCausalLM` layout) reports mean accepted length 3.43 at k=3 and single-request latency 100 ms -> 67 ms. — [open-audio-llm PR #107](https://github.com/amphionspace/open-audio-llm/pull/107)

### Inferences
- The retrofit is feasible and a public toolchain exists (AngelSpec), but the published evidence is one table row for Qwen3-8B. On that row the single-layer MTP block is clearly the weakest drafter per step (3.24 versus 4.57-5.41 for 5-layer block-diffusion drafters trained on the same data); its advantage is cost per draft step and native support in serving stacks.
- Because stock vLLM/SGLang only load MTP weights for model families registered as MTP-capable, a retrofitted Qwen3-8B block will probably need either a custom model class or packaging in the EAGLE-style drafter layout (structurally a one-layer EAGLE head is close to the MTP block: both fuse the trunk hidden state with a token embedding and run one decoder layer into the shared LM head).

### Gaps
- No released weights for a Qwen-style MTP block on Qwen3-8B (or any model lacking a native head) were found on Hugging Face; I could not verify whether the AngelSpec repository ships the Qwen3-8B checkpoint.
- Search coverage of GitHub and Hugging Face was limited to a handful of queries; smaller community projects may exist that were not surfaced.
- No blog post or paper was found comparing a retrofitted MTP block with an EAGLE-3 head on the same Qwen3 model.
