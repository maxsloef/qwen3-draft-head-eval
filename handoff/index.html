Which published draft head best predicts Qwen3-8B's future tokens

We wanted a small head that reads Qwen3-8B's own hidden states and predicts the tokens it will produce next, for an interpretability project. Four such heads are already public, so we scored them against each other instead of training one.

The answer

Use Tengyunw if any of the text involves thinking mode; use WhiFlash if it is strictly thinking off.

WhiFlash is the best predictor on ordinary answers (75% top-1 on its first prediction) but loses about 10 points on reasoning text. Tengyunw is close behind on answers (72%) and holds 71% on reasoning text. RedHatAI is third in both; AngelSlim is last in both.

Base model: huggingface.co/Qwen/Qwen3-8B. All four are heads on the frozen base model, not separate draft models. They cannot run without it.

How this started

Qwen3.5 ships with a built-in multi-token-prediction (MTP) module: one extra transformer block that takes the trunk's hidden state plus the next token's embedding and predicts the token after that. In Qwen3.5-4B it is 15 tensors, about 120.6M parameters. Qwen3-8B has no such module, and the question was how hard it would be to add one.

A literature review found that this retrofit is routine. The standard recipe is EAGLE-3: one transformer layer of about 0.4B parameters, trained on a frozen base model with roughly 0.5M conversations (about 1B tokens) whose responses are regenerated by the base model itself. Four independent EAGLE-3 heads for Qwen3-8B were already on Hugging Face, so the plan changed from training a head to choosing one.

The model cards could not settle the choice. Each reports numbers from a different server, draft shape, temperature and benchmark, and they measure serving speed, not prediction quality. So we ran one matched evaluation.

What an EAGLE-3 head does

input
At position i: the trunk's hidden states at i (taken from three depths and fused by a linear layer) and the embedding of token i+1.
step 1
Predicts token i+2, the token after next.
step 2 to 7
Feeds its own output back in as the hidden state, with the next token's embedding, and predicts one token further each time.
output
A distribution over a reduced vocabulary of 32,000 tokens, mapped back to Qwen3's 151,936.

Three properties matter for interpretability work:

  • It predicts the model, not the text. The heads are trained to match Qwen3-8B's own output distribution.
  • It reads three trunk layers, not just the last. The inputs to layers 2, 18 and 33 of 36. A claim that future tokens are decodable is a claim about that combination.
  • It has a vocabulary ceiling. Between 3% and 6% of the tokens Qwen3-8B produced in this evaluation fall outside each head's 32K vocabulary and can never be predicted.

How the heads were scored

  • Prompts: all 480 Spec-Bench prompts (chat, translation, summarisation, question answering, math, retrieval-augmented answers), first turn only.
  • Generations: Qwen3-8B answered each prompt greedily, up to 256 new tokens, once with thinking off and once with thinking on.
  • Scoring: the full sequence was run back through Qwen3-8B to get its real hidden states. Each head then predicted, at every generated position, the tokens the model actually produced 1 to 7 steps later. Earlier draft tokens were given as the correct ones.
  • Sample size: 76,316 positions with thinking off and 120,000 with thinking on. Every head saw exactly the same positions.
  • Implementation: the head's forward pass was re-implemented from the SafeAILab and RedHatAI reference code, because the serving stacks only report throughput.

  • Distribution match agrees with top-1. Overlap with the model's own next-token distribution (1 minus total variation) on step 1, thinking off, is 0.71 for WhiFlash, 0.68 for Tengyunw, 0.63 for RedHatAI and 0.53 for AngelSlim.

  • Task matters. With thinking off, extraction, coding and math are easiest; translation and roleplay are hardest. WhiFlash leads in every one of the 13 categories.

How far to trust this

  • It reproduces two model cards. AngelSlim's card reports 1.99 tokens per cycle with a 2-token chain; this run implies 1.89. RedHatAI's reports 2.1 to 2.5 with a 3-token chain; this run implies 2.34.
  • The input conventions were checked empirically. Each head was also scored with the alternative residual and layer conventions. The three SafeAILab-format heads clearly prefer the documented one.
  • RedHatAI has a small ambiguity. It scores about one point higher when fed trunk layers one deeper than documented (0.684 against 0.671 on step 1). This does not change its rank. The tables use the documented layers.
  • Greedy decoding only. Sampled text was not tested.
  • One benchmark. WhiFlash's own card also evaluates on Spec-Bench, so it is at least a familiar distribution for that head.
  • Thinking-on covers only the first 256 tokens, which is all reasoning text and no final answer.

To rerun, from a clone of the repo with a Modal account set up:

uv run --no-project --python 3.12 --with modal \
  modal run --detach modal_eval.py::main --n-shards 4 --tag main

The job expects a Modal volume named owl-hf holding a Hugging Face cache with Qwen/Qwen3-8B; the README says how to point it at your own. Head weights are downloaded automatically. The full run took 8 L40S containers. The spend was not measured.

Details that took effort to find

  • Token alignment. The token sequence is shifted by one against the hidden states: position i gets the embedding of token i+1.
  • Which layers. The three features are the inputs to trunk layers 2, 18 and 33, which are hidden_states[2], [18] and [33] in Hugging Face output.
  • Later steps skip the fusion layer. From step 2 the head's own pre-norm output is used directly as the feature.
  • Residual convention differs. RedHatAI normalises the feature before taking the residual; the other three take the residual first.
  • RedHatAI ships its own embedding table, and it is not identical to the base model's. That is why its file is 1.02B parameters against 0.4B for the others.
  • Vocabulary mapping is an offset. Target token id = draft index + d2t[draft index].
  • Two checkpoints are pickle files. Tengyunw and AngelSlim ship pytorch_model.bin; load them with weights_only=True.

Open questions for whoever picks this up

  • Is the three-layer input acceptable? If the interpretability question needs a head that reads only the final layer, none of these four qualifies. A Qwen3.5-style MTP block for Qwen3-8B has been reported by Tencent's AngelSpec, but no downloadable weights were confirmed, so that route means training one.
  • Does the 32K vocabulary matter? It hits rare and non-English tokens hardest.
  • Sampled text. If the downstream use involves temperature above zero, rerun the evaluation on sampled generations.
  • What Tengyunw was trained on. Its robustness on reasoning text suggests its training data included thinking traces, but the card does not say.
  • Training cost if one is needed. No source publishes an end-to-end GPU-hour figure for an 8B model. One paper says 200 to 300 GPU-hours; a 2-epoch run over 1B tokens may be tens of GPU-hours by one toolkit's measured throughput.
